# NPCMemoryVillage Assets

This folder contains the Unity source assets for the persistent-memory NPC village. It is an **Assets folder**, not a complete Unity project. Copy it into a Unity project or use it from the matching project already committed in the repository.

## What's in this folder

```text
Assets/
├── Editor/
│   └── VillageBuilder.cs
├── Scenes/
│   └── .keep                         # Unity scene is generated by the builder
└── Scripts/
    ├── Backend/
    │   ├── BackendConfig.cs          # API URL, request fields, player ID
    │   ├── NpcBackendClient.cs       # POSTs dialogue to FastAPI
    │   └── PlayerIdPrompt.cs         # Startup player ID screen
    ├── NPC/
    │   ├── NPCIdentity.cs            # Stable NPC ID, visible name, role
    │   ├── NPCNameTag.cs             # Name drawn above the NPC
    │   └── NPCWander.cs              # Local wandering and talk-time pause
    ├── Player/
    │   ├── OrbitCamera.cs            # Right-mouse orbit camera
    │   └── ThirdPersonController.cs  # WASD movement and gravity
    ├── UI/
    │   └── DialoguePanel.cs          # Conversation display and send action
    └── World/
        ├── WorldInteractor.cs        # Mouse, E key, range, and raycasts
        └── WorldProp.cs              # Inspectable object text
```

`VillageBuilder.cs` adds the scene objects, saved materials, player, camera, NPCs, UI, event system, and lighting. It creates these stable NPC IDs:

| Name | `npc_id` | Role |
| --- | --- | --- |
| Arthur | `Arthur` | Village elder |
| Mira the Smith | `Blacksmith` | Blacksmith |
| Tomas | `TavernKeeper` | Innkeeper |
| Lena | `VillageGuard` | Guard |

The villagers are primitive humanoid blockout meshes. They wander within local areas and pause when their dialogue is open. Rigged human characters and walk/talk animation clips are not included.

## Import and create the scene

1. Install Unity Hub and a compatible Unity Editor. In Unity Hub, create a project with the **3D (URP)** template, or open the Unity project that contains this `Assets` folder.
2. If this folder is not already in the project, copy/merge it into the project's root. Do not open the `Assets` folder by itself as a Unity project. Wait for Unity to import and compile the scripts.
3. The scripts use Unity's older Input Manager APIs. Go to **Edit → Project Settings → Player → Active Input Handling** and choose **Both** or **Input Manager (Old)**. Restart Unity if it asks.
4. Choose **NPC Memory → Build Demo Village** from the Unity menu. The builder generates and saves `Assets/Scenes/Village.unity` plus persistent `.mat` files under `Assets/Materials`. Open the generated scene if needed.
5. Create the backend config asset as described below. Press **Play** to run the scene.

The ZIP contains the builder and source scripts; the `.keep` file only preserves the `Scenes` directory. `Village.unity` is generated inside the Editor by the menu command and is not baked into this Assets package. If you commit the generated project to GitHub, include `Village.unity`, material assets, and their Unity `.meta` files.

## Connect to FastAPI

1. Create **Assets → Create → NPC Memory → Backend Config** and name the asset `BackendConfig`.
2. For the isolated browser-demo backend, set:

   | Field | Value |
   | --- | --- |
   | `baseUrl` | `http://127.0.0.1:8001` |
   | `chatPath` | `/chat` |
   | `playerId` | `karan` for the earlier Karan/Arthur test |
   | `playerIdField` | `player_id` |
   | `npcIdField` | `npc_id` |
   | `messageField` | `message` |
   | `replyField` | `reply` |

   The backend request is `POST /chat` with `{"player_id":"karan","npc_id":"Arthur","message":"Hello"}`. The reply is typically `{"npc_id":"Arthur","reply":"..."}`. Match the asset fields to your FastAPI `/docs` if your server differs.
3. In the generated scene's Hierarchy, select **NPC Backend Client** and assign the `BackendConfig` asset to its **Config** field. This assignment is required by the startup player-ID screen.
4. Start Ollama and FastAPI when you want NPC-generated replies. The demo launcher on Windows is `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run_demo.ps1` from `backend`; it serves port 8001 and uses `npc-memory-browser-demo/demo.sqlite3`. On macOS, the direct Uvicorn option from `backend` is:

   ```bash
   python3.12 -m venv .venv
   source .venv/bin/activate
   python -m pip install -r requirements.txt
   python -m uvicorn main:app --host 127.0.0.1 --port 8000
   ```

   For this option set `baseUrl` to `http://127.0.0.1:8000`; it uses the ordinary backend database, not the isolated browser-demo database. In either case, point Unity at the actual running server/database.
5. Press **Play**, click the player-ID field, enter a case-sensitive ID, and select **Enter Village**. To continue Karan's existing Arthur memory, enter `karan` and talk to Arthur. The ID screen remembers the last selection on this computer.

The local Unity-to-FastAPI chat round trip has completed successfully: a message sent from Unity received and displayed the backend's NPC reply. Unity sends both `player_id` and the selected NPC's `npc_id`; the backend scopes history using that pair. For example, `karan`/`Arthur` and `karan`/`Blacksmith` are separate conversation scopes. IDs are memory keys, not authentication. Facts told to Arthur are not automatically shared with the other villagers.

## Controls

- **WASD:** move the player.
- **Point + E:** talk to a nearby NPC or inspect a prop.
- **Point + left-click:** talk to the pointed NPC when nearby.
- **Right mouse + drag:** orbit the camera.
- **Escape:** close the dialogue panel.

The NPC currently being spoken to pauses while the panel is open, including while Unity waits for the backend response. Other villagers continue wandering.

## Troubleshooting

- **No movement or input errors:** set Active Input Handling to **Both** or **Input Manager (Old)** and restart the Editor.
- **404:** verify `baseUrl`, port, and `/chat` route.
- **422:** compare the three request field names with FastAPI `/docs`.
- **Connection refused or timeout:** start the FastAPI service and Ollama; verify they are reachable from the Unity machine.
- **No memory recall:** use the same database, exact case-sensitive player ID, and NPC ID that contain the memory. The browser-demo database on port 8001 is separate from the ordinary backend database on port 8000.
- **Pink objects:** rebuild with the project's active render pipeline and check that the URP pipeline asset is assigned if using URP.
- **`Can't Generate Mesh, No Font Asset has been assigned`:** the generated UI uses Unity UI `Text`, not TextMeshPro. A warning from `UnityEditor.HandleUtility.BeginHandles` while the village builds and UI text renders is an Editor-side text/handle warning, not an API failure.
- **`URP Global Settings Asset has been created`:** informational Unity message; it does not require a change.

## Keep these files in Git

Commit the source scripts, generated `Village.unity`, `.mat` assets, and their `.meta` files. Unity uses `.meta` files to keep asset GUIDs and references stable across machines. Exclude generated folders such as `Library/`, `Temp/`, `Obj/`, `Logs/`, and build output.
